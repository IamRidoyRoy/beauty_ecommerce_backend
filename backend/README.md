# Beauty E-commerce Backend API

Production-oriented Django/DRF backend for a Next.js storefront and React/Redux management dashboard. Native simple products and real variable products are first-class inventory targets.

Read `../ARCHITECTURE.md` first for the ERD, product architecture, stock architecture, lifecycles, API map, and RBAC matrix.

## Runtime

- Python 3.10+
- Django 5.2 LTS
- Django REST Framework 3.18
- PostgreSQL production / SQLite development
- Redis production / LocMemCache development
- Celery + Beat
- SimpleJWT + refresh blacklist
- django-filter
- drf-spectacular
- django-cors-headers
- Pillow

## Local development

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python manage.py makemigrations
python manage.py migrate
python manage.py seed_full_demo
python manage.py runserver
```

Development defaults to SQLite, LocMemCache, console notifications, and eager Celery. Redis is not required.

## Tests

```bash
python manage.py test
python manage.py check
python manage.py spectacular --file schema.yml --validate
```

Tests cover native simple/variable products, product/variant images, anonymous cart, missing variant validation, stock limits, no-user-on-browse/cart, successful guest account creation, existing-phone protection, failed-checkout rollback, simple/variant stock, partial/full purchase receive, double-receive prevention, transfer, reserve/release/consume lifecycle, invalid order transitions, refund limits, verified reviews, and staff-role permissions.

## Production

Copy `.env.example` to `.env`, use a strong secret, PostgreSQL `DATABASE_URL`, Redis `REDIS_URL`, explicit hosts/origins, and provider credentials. Then:

```bash
python manage.py migrate
python manage.py collectstatic --noinput
gunicorn config.wsgi:application --bind 0.0.0.0:8000
celery -A config worker -l info
celery -A config beat -l info
```

Or use the included Dockerfile/docker-compose services.

## Important service boundaries

Critical business operations live in `services.py`, not `ModelViewSet` methods:

- cart add/update and inventory-target validation
- checkout
- stock reserve/release/consume/increase/decrease/adjust/transfer
- purchase receiving
- order transitions
- coupon/promotion calculation
- returns/refunds
- payment idempotency boundary
- notification queueing

Query-heavy read paths and reports live in `selectors.py` and use `select_related`, `prefetch_related`, annotations, aggregation, `Exists`, and `Subquery` where appropriate.

## External providers

Pathao, Steadfast, RedX and Google auth are explicit adapter extension points. The repository does not pretend to call live providers without credentials. Payment webhooks have an idempotency event table/service boundary ready for provider-specific signature verification and mapping.

## Migrations note

This source bundle was generated in an execution environment where Django packages could not be downloaded, so autogenerated migration files were not fabricated by hand. After dependency installation, run `python manage.py makemigrations` once, review the generated SQL, commit those migrations to your deployment repository, then run the full test/check/schema commands above before release.
